# 進銷存第一階段：進貨品名與倉庫料號核對

來源：公司區網 `115進貨明細表.xlsx`，`仂邁1`，民國 115 年 9／10 月。
正式庫存、BOM、交易仍以原 Supabase 模組為準；本模組沒有庫存寫入路徑。

## 畫面與資料

- 導覽「進銷存」置於庫存之後；第一版提供進貨明細、料號對照、期間進出核對。
- 每個來源列保留原始廠商、品名、數量、單價、小計與 Excel 列號。發票／帳款總計、銀行、支票不帶入；小計相加不稱為含稅進貨金額。
- 僅解析具有數值數量的明細列。排除月份標題、總計、純公式空白；有品名卻沒有數值數量會列於來源報告，不默默補 0。
- 來源版本以檔案 SHA256＋月份去重。舊快照保留，重送不會建立第二批；不會重新選舊批成為最新版本。
- 以「原始廠商＋原始品名」保存跨月份對照。精確／相似候選均須人工選擇；不得自動合併或更名倉庫料號。
- 對照清單可篩選精確待確認、相近待確認、找不到候選；各狀態數字以廠商＋品名組數為單位。可下載目前篩選的 CSV 核對清單，保留原始品名、候選料號、來源列及空白人工確認欄，不會執行確認或庫存異動。
- 候選排序優先完整符號比對、補倉庫前綴後完整相符，再列一般字元相似；數字／尾碼不同不得自動視為相同。
- 料號對照在頁內逐筆操作：電腦左側為原始廠商／品名，右側為建議或已確認料號；手機以同筆卡片上下排列。點候選只暫選，必須按「確認並儲存這筆對照」才送出。取消、切換條件或查下一筆不會自動寫入；編輯期間禁止切換條件以避免遺失輸入。
- 儲存完成會顯示原品名→料號的結果，可按「下一筆待確認」繼續。找不到候選可頁內搜尋或標示非物料；無需 Excel。數量單位換算為選填的展開區，未確認單位不計算數量差異。
- 背景重繪或切回此頁會還原目前草稿的料號選擇、分類、換算與備註；儲存中仍鎖定，結果不確定時保留錯誤並禁止重送。原缺口：重繪後料號下拉選單回空白，且非同步錯誤可能寫入已被替換的 DOM；已加隔離電腦／手機的重繪、延遲成功／失敗驗收。
- 可指定既有料號、非物料／費用、撤回至待確認；換算係數未確認時不計算數量差異。原表沒有單位欄，不推測公斤、個、包。
- 期間核對只讀原有完整期間總表的進貨入庫，不混入生產產出、退貨與轉庫。帳務月份與實際入庫月份不同時，數量差異不是庫存故障證據。
- 不提供自動建立料號、補入庫或調整庫存。尚未做銷貨、成本結算、付款及無人區網監看。

## 系統試跑（未核定）

預設先顯示試跑模型，無需先完成每筆對照。優先使用人工確認；未確認者以第一個候選暫配，疑似運費／保險／餐費等暫列費用，沒有候選及失效的人工料號保留未配。未確認數量單位時，試跑暫按 1:1，逐筆標示「單位假設」，不改變正式核對頁的未知單位規則。
模型顯示帳務暫換算量、正式期間進貨入庫、領料／出庫及帳面期初末；領料不是銷貨。沒有期間交易時，入庫可為 0，期初末仍未知。總表失敗／不完整時不計算差異。暫算差異不是庫存錯誤或補庫依據。
暫配只在瀏覽器計算，不存入 erp_purchase_mappings，也不變動任何物料／BOM／庫存。由「檢查／校正這筆」回到原始品名的頁內確認，人工按儲存後才寫入對照。重新試跑讀取最新來源、對照、倉庫料號及期間總表。

## 權限與稽核

沿用公司 Token＋角色。Vic／廠長／採購／倉管可檢視與確認對照；只有 Vic／廠長／採購可匯入。AI 僅檢視。業務／品管／一般檢視未開放財務來源。
後端逐路徑驗證角色與 Token。Supabase 三張專用表開 RLS，撤銷 anon/authenticated 直連存取；僅服務角色呼叫。
對照使用版本 CAS 與 request UUID，競爭更新會阻擋並要求讀回；同請求重試回傳原稽核結果。保存前後資料、時間與角色（不是個人身分認證）。
儲存或讀回不確定時，前端禁止原表單重送，提示重新讀取查驗。撤回確認保留稽核，不刪紀錄。

雲端不能直接讀區網，目前由此受控工具更新快照；尚未建立定時同步。

## 驗收與回復

- Node：候選不自動確認、不同廠商不互相污染、費用與未知單位、期間空值、授權與唯讀、來源去重、只寫專用中繼資料。
- 隔離 PostgreSQL：相同請求重試、並行 CAS、跨組織料號、角色、庫存未變。
- 電腦／390px 手機：月份切換、搜尋、人工選料號、儲存讀回、失敗禁止重送、費用處理、期間核對與 AI 唯讀。
- 撤回部署可隱藏頁面／API，保留新表及快照；不得以回復程式為名刪除來源或變動庫存。
