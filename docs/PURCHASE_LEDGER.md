# 進銷存第一階段：進貨品名與倉庫料號核對

來源：公司區網的年度進貨明細表（例如 `115進貨明細表.xlsx`），工作表 `仂邁1`。
正式庫存、BOM、交易仍以原 Supabase 模組為準；本模組沒有庫存寫入路徑。

## 三個人員工作入口（2026-11-20）

- **每月物料進出總表／倉管**：沿用完整正式期間報告，按倉庫／料號列期初、入料、組立、回料、領料、轉入轉出、調整、其他增減與期末。搜尋、漸進顯示及精確倉庫／物料交易明細；Excel 有完整彙總／逐筆兩張表，A4 橫式列印／PDF 同樣包含全月，不受畫面篩選限制。交易鏈異常的期初末保留未知；沒有交易的料號不列，未鎖定月結。
- **進貨待核清單／採購與行政**：依原始廠商＋品名列配號、失效、單位問題；僅已確認料號及換算才按 SKU 列正式入庫差異。可篩原因、下載 CSV、回查來源／既有對照與正式交易。未取得完整總表時只顯示可判定問題，明示入庫差異尚未檢查；不自動結案、不新增補庫、不另寫處理狀態。人工修正對照後重新讀取可重算，沒有待核不等於已盤點。
- **採購與用料概覽／主管**：來源小計、供應商數、可判定待核及領料／出庫料號數；月別來源金額與供應商來源小計排行、按單位分看的領料／出庫排行。本月與上一個已匯入月份作唯讀比較；未知金額保留空值，不跨料號加總總數量。來源小計含待配號及費用，非含稅帳款／已確認物料採購成本；領料含出貨、非銷售或已實際耗用，不把轉庫及調整納入用料排行。每個供應商可回查來源列。
- 預設概覽，三個工作入口在上方；原有試跑、料號對照、進貨明細與期間核對保留在「料號與來源核對工具」。既有人工確認、CAS、重試保護及角色權限不變。
- 月份選單從已匯入快照自動產生，預設最新。未建立訂單銷售、成本／毛利、庫齡或預測模型。查詢、導覽、下載、列印均只讀資料，不會建立交易或覆蓋對照。

## 畫面與資料

- 導覽「進銷存」置於庫存之後；第一版提供進貨明細、料號對照、期間進出核對。
- 每個來源列保留原始廠商、品名、數量、單價、小計與 Excel 列號。發票／帳款總計、銀行、支票不帶入；小計相加不稱為含稅進貨金額。
- 僅解析具有數值數量的明細列。排除月份標題、總計、純公式空白；有品名卻沒有數值數量會列於來源報告，不默默補 0。
- 來源版本以單月內容 SHA256＋月份去重。舊快照保留，重送不會建立第二批；不會重新選舊批成為最新版本。
- 以「原始廠商＋原始品名」保存跨月份對照。精確／相似候選均須人工選擇；不得自動合併或更名倉庫料號。
- 對照清單可篩選精確待確認、相近待確認、找不到候選；各狀態數字以廠商＋品名組數為單位。可下載目前篩選的 CSV 核對清單，保留原始品名、候選料號、來源列及空白人工確認欄，不會執行確認或庫存異動。
- 候選排序優先完整符號比對、補倉庫前綴後完整相符，再列一般字元相似；數字／尾碼不同不得自動視為相同。
- 料號對照在頁內逐筆操作：電腦左側為原始廠商／品名，右側為建議或已確認料號；手機以同筆卡片上下排列。點候選只暫選，必須按「確認並儲存這筆對照」才送出。取消、切換條件或查下一筆不會自動寫入；編輯期間禁止切換條件以避免遺失輸入。
- 儲存完成會顯示原品名→料號的結果，可按「下一筆待確認」繼續。找不到候選可頁內搜尋或標示非物料；無需 Excel。數量單位換算為選填的展開區，未確認單位不計算數量差異。
- 背景重繪或切回此頁會還原目前草稿的料號選擇、分類、換算與備註；儲存中仍鎖定，結果不確定時保留錯誤並禁止重送。原缺口：重繪後料號下拉選單回空白，且非同步錯誤可能寫入已被替換的 DOM；已加隔離電腦／手機的重繪、延遲成功／失敗驗收。
- 更換選定料號時，只清除未儲存草稿的單位確認與換算係數，提示重新核對。重選同料號或僅開啟既有對照不會清除原係數；取消編輯不改正式對照及備註。避免把料號 A 的換算套到 B。
- 可指定既有料號、非物料／費用、撤回至待確認；換算係數未確認時不計算數量差異。原表沒有單位欄，不推測公斤、個、包。
- 期間核對只讀原有完整期間總表的進貨入庫，不混入生產產出、退貨與轉庫。帳務月份與實際入庫月份不同時，數量差異不是庫存故障證據。
- 正式期間核對以已確認倉庫料號為分母，將數量不同／一致／單位或資料待確認分成互斥狀態，統計與篩選使用同一計算。未確認品名／費用不納入；未知不算一致，部分總表拒絕計算。可展開同料號的原始廠商、Excel 列號、來源數量與各自換算，以及正式交易。
- 不提供自動建立料號、補入庫或調整庫存。尚未做銷貨、成本結算、付款。

## 系統試跑（未核定）

預設先顯示試跑模型，無需先完成每筆對照。優先使用人工確認；未確認者以第一個候選暫配，疑似運費／保險／餐費等暫列費用，沒有候選及失效的人工料號保留未配。未確認數量單位時，試跑暫按 1:1，逐筆標示「單位假設」，不改變正式核對頁的未知單位規則。
模型顯示帳務暫換算量、正式期間進貨入庫、領料／出庫及帳面期初末；領料不是銷貨。沒有期間交易時，入庫可為 0，期初末仍未知。總表失敗／不完整時不計算差異。暫算差異不是庫存錯誤或補庫依據。
試跑提供料號未確認、單位假設、無期間交易、有異動但無進貨入庫、暫算數量不同、多原品名暫配同料號等核對提示及篩選；一個料號可重複歸類，各類數量不能相加。跨月只是待查可能性，不宣稱已找出根因。可直接跳到來源品名核對換算，並在同頁展開正式期間交易（精確 SKU，依時間排序，顯示前 10 筆及完整筆數）；交易資料缺失與真正 0 筆分開呈現。
交易明細可按「再顯示 10 筆交易」逐步查看完整已取得紀錄，保留展開狀態並顯示目前筆數／總筆數及倉庫，不會把前 10 筆當作全部。試跑與正式核對共用此唯讀明細。
暫配只在瀏覽器計算，不存入 erp_purchase_mappings，也不變動任何物料／BOM／庫存。由「檢查／校正這筆」回到原始品名的頁內確認，人工按儲存後才寫入對照。重新試跑讀取最新來源、對照、倉庫料號及期間總表。

## 權限與稽核

沿用公司 Token＋角色。Vic／廠長／採購／倉管可檢視與確認對照；只有 Vic／廠長／採購可匯入。AI 僅檢視。業務／品管／一般檢視未開放財務來源。
後端逐路徑驗證角色與 Token。Supabase 三張專用表開 RLS，撤銷 anon/authenticated 直連存取；僅服務角色呼叫。
對照使用版本 CAS 與 request UUID，競爭更新會阻擋並要求讀回；同請求重試回傳原稽核結果。保存前後資料、時間與角色（不是個人身分認證）。
儲存或讀回不確定時，前端禁止原表單重送，提示重新讀取查驗。撤回確認保留稽核，不刪紀錄。
Pages 發布會將進銷存 helper 加上 build 版本，避免新 HTML 配到舊快取程式；Service Worker 對 helper 採網路優先、離線保留快取。部署不強制 SKIP_WAITING，讓使用者先完成編輯再套用更新。

## 受控來源匯入

在能讀區網的公司電腦執行：

```powershell
python scripts/import_purchase_ledger.py
# 看預檢筆數後，使用既有環境憑證：
python scripts/import_purchase_ledger.py --apply
```

腳本不列印憑證。正式原始資料與執行輸出不得加入 Git 或公開 Pages。
雲端無法直接讀區網。公司電腦定期執行同一工具，從 2026-09 起掃描年度明細（不匯入未來月份），已存在且內容相同的月份略過。寫入後讀回批次與內容；同月少於上一版時保留原先快照供核對。按廠商與科目彙總的每月進貨檔沒有品名明細，保留給原報表用途。

## 驗收與回復

- Node：候選不自動確認、不同廠商不互相污染、費用與未知單位、期間空值、授權與唯讀、來源去重、只寫專用中繼資料。
- 隔離 PostgreSQL：相同請求重試、並行 CAS、跨組織料號、角色、庫存未變。
- 電腦／390px 手機：月份切換、搜尋、人工選料號、儲存讀回、失敗禁止重送、費用處理、期間核對與 AI 唯讀。
- 撤回部署可隱藏頁面／API，保留新表及快照；不得以回復程式為名刪除來源或變動庫存。
