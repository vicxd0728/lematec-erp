# C 端匯入 BOM 讀取與原預覽重試

2026-11-23：業務截圖顯示 16748～16751 的四個品項被「BOM 尚未成功載入」阻擋。唯讀查驗：正式庫存 2,028 個料號、BOM 1,454 列全部可對應；截圖四個 SKU 均有正式 BOM。這不代表已確認當時瀏覽器哪一個請求失敗，亦未代匯入／扣料。

可重現的程式缺口：核心同步先把 BOM ready 清除，且一般訂單查詢失敗會提早離開；Excel 解析後直接用當下 ready 狀態建立預覽，沒有等待資料讀取。舊預覽錯誤只能重新上傳，缺少同批唯讀重檢入口。

修正：

- 核心讀取與匯入資料讀取使用共同的序列，避免同時切換全域料號／BOM；失敗的前次讀取不會卡死後續讀取。
- 解析後與確認匯入前，先完整讀取正式 Supabase 料號及 BOM，安全對應後才在同一序列內產生預覽。這條路徑不依賴 B2B 訂單、不查 Notion 備援、不補鏡像，也不執行任何業務寫入。
- 真正讀取失敗保持阻擋，顯示實際原因；不能把它說成 BOM 缺少、料號不存在或缺料。讀取逾時可在原預覽重試。重新檢查保留同一批已解析資料，並非跨分頁或重啟後的檔案備份。
- 「重新讀取 BOM 並檢查」只讀資料，連點只執行一次；確認匯入按鈕在讀取中／失敗時不可使用。即使全部輸入列是既有訂單，來源讀取失敗也不得繼續匯入。
- 正式扣料仍須人員另外按確認；原有平台／SKU 身分、原單 ID、交易憑證、續接及防重複扣料保護保持不變。

驗收：失敗的背景 B2B 同步、首次 BOM 失敗、重試成功、原輸入保留，以及既有訂單來源讀取失敗；業務角色 1440px／390px 實際渲染器隔離驗收失敗、重試、連點及零 POST。正式站只做資料／版本讀回，未操作正式訂單與庫存。
